# 北极航线决策仿真平台使用说明书

## 1. 平台定位

本平台用于演示北极航线规划系统从环境数据到航行决策的完整链路：

```text
A 环境数据 → B 风险评估 → C 动态规划 → D 可视化仿真
```

平台消费已经发布的 JSON/PNG 演示制品。Viewer 不直接读取 A/B 的私有数据，不重新计算风险，不重新规划路线，也不修改 C 的权威路线结果。

当前平台属于科研演示和工程验证系统，风险模型、船舶参数和路线结果未经真实航行标定，不得用于真实导航、安全决策或自动驾驶。

## 2. 各工作包职责

| 工作包 | 负责内容 | 输出或作用 |
| --- | --- | --- |
| `arctic_route_contracts` | 共享场景、走廊、船舶、运行上下文、Schema 和数据契约 | 统一各包的数据格式和身份 |
| `work_package_a` | 获取、接收、标准化、质检和归档环境数据 | `DatasetBundle v2` |
| `work_package_b` | 逐小时计算风险、置信度、硬约束和环境速度因子 | `RiskFrame v2`、风险窗口 |
| `work_package_c` | 根据风险窗口和船舶配置计算速度、ETA、路线和重规划 | v2/v3 路线制品、候选路线 |
| `arctic_route_orchestrator` | 串联 A/B/C，执行身份校验、预检、超时控制、审计和展示制品导出 | `replay.viewer-bundle.v1` |
| `work_package_d` | 只读消费展示制品，渲染地图、风险、路线、船位和仿真状态 | 本可视化平台 |
| `arctic_route_governance` | 维护系统架构、边界、决策、验收标准和运行文档 | 治理依据，不参与运行时计算 |

## 3. 启动平台

在 PowerShell 中执行：

```powershell
Set-Location "D:\Arctic Route Planning\work_package_d"
$python = ".venv-win\Scripts\python.exe"
& $python scripts\replay_viewer_serve.py --root viewer --host 127.0.0.1 --port 8131
```

然后打开：

```text
http://127.0.0.1:8131/
```

如果 `.venv-win` 不存在，可使用已安装的 Python 3.13，并先按项目锁文件同步依赖。Viewer 的演示制品位于 `viewer/`，主要包括：

- `bundle.json`：Orchestrator 导出的整合展示制品
- `gebco_basemap.png`：地图底图
- `basemap_metadata.json`：底图投影和范围信息
- `replay-viewer-preflight.json`：展示前置校验结果

## 4. 首屏整合流水线

页面顶部的流水线概览用于快速确认 A/B/C/D 是否已经接通：

- **A 数据**：显示 DatasetBundle 是否已发布并可用
- **B 风险**：显示当前 RiskFrame 数量
- **C 规划**：显示候选路线数量；没有候选路线时使用权威单路线后备
- **D 展示**：表示当前 Viewer 仿真运行时已经启动

顶部的场景名称和 assembly identity 来自当前 `bundle.json`，不是页面硬编码。

## 5. 三种视图

### 5.1 研究验证

用于研究人员比较不同规划目标和规划层的路线结果。

可以查看：

- 4 个规划层：全航程、主走廊、滚动窗口、可执行窗口
- 3 个规划目标：最快路线、低风险路线、推荐路线
- 距离、航行时间、预计抵达时间
- 平均风险、最大风险和综合风险
- DatasetBundle、RunContext、RiskWindow、RiskFrame 和候选集身份
- 候选路线在地图上的几何对比

选择候选路线只改变地图高亮，不改变 C 的 `selected_candidate_id`、路线排序、几何、ETA 或风险指标。

如果候选路线制品缺失、身份不匹配、路线数量不完整或校验失败，研究验证视图会自动禁用，并回退到权威单路线展示。

### 5.2 航行仿真

用于向观众演示船舶沿权威路线航行的过程。

可以操作：

- 点击“运行/暂停”控制仿真
- 选择 1x、2x、4x、8x 仿真速度
- 拖动航程进度条跳转仿真时间
- 查看船舶当前位置、航向和已完成航迹
- 开关风险、硬约束、路线、航迹和导航辅助图层
- 选择当前、未来 6 小时、12 小时或 24 小时风险预测时域

仿真时钟是唯一主时间。船位根据已发布路线的 waypoint ETA 计算，风险帧按有效时间选择。仿真渲染不会把风险帧数量误当作播放器帧，也不会修改业务速度或路线。

### 5.3 工程调试

用于开发和验收时检查系统内部状态。

可以查看：

- 仿真时间、船舶经纬度、速度和航向
- 当前权威路线版本
- 待采用路线版本
- 重规划决定时间和实际采用时间
- 风险帧 ID、风险选择方式和当前事件
- L1/L2 门禁状态

工程调试视图适合排查时间线、路线采用时机和状态机问题，不适合直接作为正式演示主画面。

## 6. 风险预测时域

风险预测时域用于选择相对于当前仿真时间的风险信息：

- **当前**：选择不晚于仿真时间的最新有效风险帧
- **+6 小时**：选择目标时刻对应或之前的有效帧
- **+12 小时**：选择目标时刻对应或之前的有效帧
- **+24 小时**：选择目标时刻对应或之前的有效帧

当请求时刻超出正式风险窗口，平台显示“风险预测不可用”，不会复用最后一帧伪装成有效预测。

风险等级和硬约束是两套信息：`LAND`、`DATA_UNAVAILABLE`、`OTHER` 等硬约束不会被当作低风险水域。

## 7. 路线决策状态

路线决策面板会区分：

- **权威路线运行中**：当前路线有效
- **已决定重规划**：新路线已生成，但尚未采用；当前路线仍然有效
- **已采用重规划**：新路线正式成为权威路线
- **待采用路线**：展示未来可能采用的路线，不代表已经改变当前航行
- **已替代路线**：历史路线保留用于审计，不再作为当前权威路线

这种区分用于演示“重规划只影响未来”，避免出现船舶瞬移或历史路线被覆盖的情况。

航行决策时间线中的里程碑可以直接点击，平台会暂停仿真并跳转到该事件时刻；地图拖拽
后可点击“重置地图”恢复初始视图。

## 8. 地图和图层

地图使用已发布底图和统一投影，主要图层包括：

- 风险等级 1 至 5
- LAND、数据不可用和其他硬约束
- 权威未来路线
- 待采用路线和已替代路线
- 已完成航迹与近期船舶轨迹
- 当前路段和船舶位置
- 经纬网格、比例尺和正北指示

风险网格没有空间插值。路线的加密只用于屏幕绘制，不改变权威 waypoint 几何。

## 9. 风险解释

点击风险网格后，可以查看当前 RiskFrame 中发布的：

- 风险等级
- 风险分数
- 置信度

如果存在并通过身份校验的 `risk-explanation.v1` sidecar，还会显示贡献因素、原因和不确定性；sidecar 缺失或校验失败时，基础风险展示仍然可用，解释区域会安全回退为不可用。

## 10. 演示建议

推荐演示顺序：

1. 先介绍顶部 A→B→C→D 流水线和当前场景身份。
2. 在“研究验证”中展示最快、低风险、推荐三条路线的指标差异。
3. 切换到“航行仿真”，点击“运行”，展示船位和航迹随仿真时间变化；也可以点击时间线
   里的“待采用”或“已采用”里程碑，直接跳到重规划状态。
4. 切换风险预测时域，展示当前时刻和未来风险窗口的选择结果。
5. 打开风险和硬约束图层，说明风险等级与不可通行区域是分开的。
6. 最后进入“工程调试”，展示路线版本、重规划事件和 L1/L2 状态。

## 11. 不能做的事情

本平台目前不能：

- 直接下载或实时接入环境数据
- 在 Viewer 内重新计算 A/B/C 结果
- 根据风险颜色自动判断真实航行安全
- 代替船长或航海电子系统做真实导航决策
- 将缺失数据当作零风险
- 将研究候选路线当作已经执行的路线
- 将演示船舶参数描述为真实标定参数
